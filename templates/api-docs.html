Introduction

Take FIRO payments in your store, app or bot. One REST API, a hosted checkout page and signed webhooks.

How a payment works

  1. Connect your walletIn the dashboard, add a Spark view key or a wallet xpub. FiroGate can see payments. It can never spend.
  2. Create a paymentYour server calls POST /api/payments/create with the amount.
  3. Send the buyer to checkoutRedirect them to the checkout_url in the response.
  4. The buyer paysFiroGate watches the chain and waits for the confirmations you set.
  5. You get a webhookpayment.confirmed arrives at your server. Deliver the order.
Non-custodial. Funds go straight to your own wallet. FiroGate holds no spend key.

Quickstart

Four steps from a new account to a paid order.

  1. Connect a wallet and get a keyIn the dashboard, open Wallet and connect your Spark view key or xpub. Then open API & Webhooks and create an API key. It starts with fg_live_ and is shown once.
  2. Create a paymentCall the API from your server with the amount and your order ID. Never call it from a browser: the key must stay secret.
  3. Redirect the buyerSend them to checkout_url. Use the full URL: the ?t= token is required.
  4. Handle the webhookSet your webhook URL in API & Webhooks. When payment.confirmed arrives, check the signature, then mark the order paid.
No webhook yet? You can poll Get a payment every 10 to 30 seconds until status is confirmed.

2. Handle the webhook
import hashlib, hmac, json, time
from flask import Flask, request, abort

app = Flask(__name__)
WEBHOOK_SECRET = "your_webhook_secret"

@app.post("/webhooks/firogate")
def firogate_webhook():
    body = request.get_data()
    sent = request.headers.get("X-FiroGate-Signature", "")
    expected = hmac.new(WEBHOOK_SECRET.encode(), body, hashlib.sha256).hexdigest()
    if not hmac.compare_digest(expected, sent):
        abort(401)

    event = json.loads(body)
    if abs(time.time() - event["timestamp"]) > 300:
        abort(400)

    if event["event"] == "payment.confirmed":
        mark_order_paid(event["order_id"])
    return {"ok": True}
const crypto = require("crypto");
const express = require("express");

const app = express();
const WEBHOOK_SECRET = "your_webhook_secret";

app.post("/webhooks/firogate", express.raw({ type: "application/json" }), (req, res) => {
  const sent = req.get("X-FiroGate-Signature") || "";
  const expected = crypto.createHmac("sha256", WEBHOOK_SECRET).update(req.body).digest("hex");
  const ok = sent.length === expected.length &&
    crypto.timingSafeEqual(Buffer.from(sent), Buffer.from(expected));
  if (!ok) return res.sendStatus(401);

  const event = JSON.parse(req.body);
  if (Math.abs(Date.now() / 1000 - event.timestamp) > 300) return res.sendStatus(400);

  if (event.event === "payment.confirmed") markOrderPaid(event.order_id);
  res.json({ ok: true });
});

Authentication

Every request carries your API key in the X-API-Key header.

Your key

Create keys in the dashboard under API & Webhooks. A key starts with fg_live_ and is shown once, so store it right away.

  • Keep it on your server. Never put it in a web page or an app.
  • Revoke a key in the dashboard if it leaks. Other keys keep working.

Permissions

A key can be limited to some permissions when you create it. A key with no list can do everything. A call outside the key's permissions returns 403.

create_invoicewrite
Create payments.
read_invoiceread
Read payments, search, export, refund lists and Spark mints.
read_analyticsread
Summaries, sales by vendor and refund totals.
wallet_connectwrite
Connect, check or remove the Spark view key and the xpub.
manage_refundswrite
Record or remove refunds.
manage_recurringwrite
Create and manage recurring payments.

When it fails

401Unauthorized
The key is missing, wrong or revoked.
403Forbidden
The key is valid but lacks the permission for this call.

Errors

FiroGate uses normal HTTP status codes. Errors come back as JSON with one detail field.

Status codes

200OK
The call worked.
201Created
A payment, refund or recurring payment was created.
204No content
A delete worked. The body is empty.
400Bad request
A value is not allowed, for example an amount that is too small.
401Unauthorized
The API key is missing or wrong.
403Forbidden
The key lacks a permission, or a checkout token is wrong.
404Not found
No such payment, refund or recurring payment on your account.
409Conflict
The store has no wallet connected yet.
422Validation
A field is missing or has the wrong type or format.
429Too many requests
You hit a rate limit. Wait a minute and try again.
503Unavailable
The Firo node is offline. Try again shortly.

Rate limits

Creating payments is limited to 120 requests a minute per IP address. Cancelling is limited to 5 a minute.

Handling errors

  • Retry 429 and 503 after a short wait.
  • Do not retry 400, 401, 403 or 422. Fix the request first.
  • It is safe to send the same order_id again: you get the same payment back.

Self-hosting

Run FiroGate on your own server. You need a Linux machine and a synced Firo Core node.

Run FiroGate on your own server. You need a Linux VPS and a synced Firo Core node.

Requirements

Firo Corev0.14+Full node, synced and running
CPU2 cores+More recommended if running Firo Core on the same machine
RAM2 GB+Higher recommended when co-hosting Firo Core or a database on the same machine
Storage15 GB+Excludes Firo blockchain data if node is hosted separately
reverse proxyoptionalTLS-terminating proxy for production

1. Clone and configure

# Clone the repository
git clone https://github.com/firogate/firogate-ce.git
cd firogate-ce

# Copy the example config
cp .env.example .env

2. Generate secret keys

python3 -c "import secrets; print(secrets.token_hex(32))"
# → paste as SECRET_KEY in .env

python3 -c "import secrets,base64; print(base64.urlsafe_b64encode(secrets.token_bytes(32)).decode())"
# → paste as FIELD_ENCRYPTION_KEY in .env

3. Set required .env values

# .env minimum required fields
SECRET_KEY=your_generated_key
FIELD_ENCRYPTION_KEY=your_generated_key
BASE_URL=https://yourdomain.com

# Firo Core node (must match your firo.conf)
FIRO_RPC_USER=your_rpc_user
FIRO_RPC_PASSWORD=your_rpc_password

# Operator account email(s), comma-separated
OPERATOR_EMAILS=you@yourdomain.com

4. Start the server

# Build and start, backgrounded
docker compose up -d

# Follow logs
docker compose logs -f

5. Configure Firo Core (firo.conf)

# ~/.firo/firo.conf
rpcuser=your_rpc_user
rpcpassword=your_rpc_password
rpcallowip=127.0.0.1
rpcport=18888
server=1
txindex=1
addressindex=1  # for transparent payments and Spark mints
mobile=1  # required enables the Spark RPC methods FiroGate uses
Enabling mobile=1 on a node that already has a synced block index triggers a one-time Spark-state rebuild on the next startup this can take hours with no progress logged, and looks identical to a hang at "Loading block index...". Set mobile=1 before your first sync if possible, or budget for a slow one-time restart.
For reverse-proxy, Tor onion, and service configuration see the docs/ folder in the repository.

6. Running as a private instance

FiroGate Community Edition is built around a single operator account. If you are running it as a private, internal payment system, an administrator can disable the public login and register pages entirely from the dashboard's Security → Diagnostics section. Once disabled, /login and /register return a 404 to any visitor, while an already-signed-in operator session keeps working normally.

Webhooks

Verify signatures

Check that a webhook really came from FiroGate before you trust it.

How it works

  1. Read the raw bodyUse the exact bytes you received, before any JSON parsing.
  2. Compute the signatureHMAC-SHA256 of those bytes with your webhook secret, written as hex.
  3. CompareIt must equal the X-FiroGate-Signature header. Use a constant-time compare.
  4. Check the timeRefuse the webhook if timestamp is more than 5 minutes old.
Your webhook secret is in the dashboard under API & Webhooks. It is not your API key.

Webhook handler

import hashlib, hmac, json, time
from flask import Flask, request, abort

app = Flask(__name__)
WEBHOOK_SECRET = "your_webhook_secret"

@app.post("/webhooks/firogate")
def firogate_webhook():
    body = request.get_data()

        mark_order_paid(event["order_id"])
    return {"ok": True}

Marketplace

Track which seller each payment belongs to, and split the money in your own system.

Use the metadata field to track seller/vendor context through every payment and webhook. FiroGate stores whatever you send and echoes it back in all events including retries.

FiroGate does not split payments automatically. Marketplace commission logic runs on your platform metadata gives you the seller context to do it.

def handle_confirmed(data):
    meta            = data.get("metadata", {})
    vendor_id       = meta.get("vendor_id")
    comm_pct        = meta.get("commission_pct", 0)
    amount_received = data["amount_received"]

    platform_cut  = amount_received * (comm_pct / 100)
    seller_share  = amount_received - platform_cut

    mark_order_paid(data["order_id"])
    credit_seller(vendor_id, seller_share)

Tor and onion

Use the same API over a Tor onion address.

FiroGate supports a .onion hidden service. One onion address serves the API, checkout, and dashboard no subdomain routing needed.

Same API, different base URL. Replace {{ api }} with your .onion address. Every endpoint, header, and response is identical.

Environment Variables

ONION_URLstring
Full .onion base URL e.g. http://yourxxx.onion
TOR_ENABLEDbool
Route outbound .onion webhook calls through the local SOCKS5 proxy
TOR_SOCKS_PORTint
Local SOCKS5 proxy port (default: 9050)
TOR_ALL_TRAFFICbool
Route ALL outbound HTTP through Tor not just .onion URLs

Tor Hidden Service (torrc)

Point HiddenServicePort to your backend. The generated hostname file is your ONION_URL value.

HiddenServiceDir /var/lib/tor/firogate/
HiddenServicePort 80 127.0.0.1:8000
